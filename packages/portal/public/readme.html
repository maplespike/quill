What it is

MapleSpike ingests, verifies, and surfaces 198 data modules from Canadian government and other public-sector sources. Source terms vary by publisher and dataset; public availability does not establish reuse rights. Records carry source provenance and, where supported, a SHA-256 hash of Quill's canonical record JSON for integrity checks.

Current metrics: docs/metrics.json — 198 modules · 164 MCP tools · ~191K lines TS · 14 packages. Latest reviewed 2026-06-19.

Quick start

Install dependencies and run the MCP server locally — works straight out of the box:

# Install dependencies (workspace protocol)
pnpm install

# Build all packages
pnpm run build

# Start MCP server (local stdio)
cd packages/mcp-server
pnpm start

All 164 MCP tools return real data — committees, corporate, influence, and government data are all searchable via the SQLite database. No external database configuration required for MCP tools.

Running the local stack & smoke test

The scripts/dev-up.sh wrapper handles env bootstrap, image build, and docker compose orchestration. scripts/e2e-smoke.sh confirms all three runtime services came up healthy. Both scripts live in the repo so they stay authoritative — prefer them over raw docker compose, which has known port-mapping and fallback drift across v1 and v2.

Prerequisites: Docker Desktop 4.x+ or the docker-compose-plugin; ~4 GB RAM; ports 8082 (API), 3001 (MCP), 8080 (Portal). No host-side pnpm install needed — the Dockerfile runs it inside the image.

Bring the stack up

./scripts/dev-up.sh                  # foreground, builds, waits for /v1/health
./scripts/dev-up.sh --detach        # background
./scripts/dev-up.sh --rebuild       # full image rebuild
./scripts/dev-up.sh --logs          # tail logs of running stack
./scripts/dev-up.sh --down          # tear down (orphans, no -v)

Run the end-to-end smoke test

./scripts/e2e-smoke.sh --mode=compose --up --down   # self-contained
./scripts/e2e-smoke.sh --mode=local                  # against an already-running stack
./scripts/e2e-smoke.sh --mode=local \
  --api=http://staging.lan:8082 \
  --portal=http://staging.lan:8080 \
  --mcp=http://staging.lan:3001

CI/CD

GitHub Actions drives the two-environment deployment model.

BranchWorkflowAction
mainCI (ci.yml)Run tests on every push
mainDeploy Dev (deploy-dev.yml)Build + deploy to maplespike-dev namespace
prodDeploy Prod (deploy-prod.yml)Build + deploy to quill-prod namespace

Container images are tagged :dev for dev builds and :latest for production. Each workflow builds, pushes to the registry, and applies the corresponding k8s/dev/ or k8s/prod/ Kubernetes manifests.
