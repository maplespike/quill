# Quill claim provenance evidence v1

Claim verification responses expose `provenance_evidence` for store-backed claim bundles. It is an evidence inventory, not a source-authenticity, accuracy, copyright, or reuse-rights conclusion.

## Evidence fields

- `record_integrity` is SHA-256 over Quill's recursively key-sorted canonical JSON representation of the claim value (`quill-canonical-json-v1`). This hash identifies that representation only; it is not a digest of source response bytes.
- `acquisition.artifacts` records valid explicit record-supplied evidence and matching HTTP response artifacts seen by the shared `httpGet` client during `runModule`: redacted request URL, capture timestamp, status, selected response headers, body length, and SHA-256 over the UTF-8 encoding of the response body string exposed by that client. Each artifact has its own association state. A body that the client fully reads is `complete-http-client-body`, including a zero-length body whose digest is SHA-256 of the empty string. This is the client-visible body, not necessarily wire-level bytes (decompression/decoding may have occurred).
- `acquisition.association` is `url-matched-not-content-verified` only when valid absolute HTTP(S) URLs match after query, fragment, and credentials are removed. It records URL equality only; it does not establish that a response contains or generated a record. Each artifact records its origin as `explicit-record-evidence` or `shared-http-client-capture`; unmatched explicit evidence is retained with association `not-established`, while unmatched ambient request captures are not attached. Empty, relative, malformed, and non-HTTP(S) URLs never match. Multiple matching request artifacts (for example, retries) are retained in capture order. If no artifact is retained the association is `none`; retained but unmatched explicit evidence is `not-established`.
- `transformations.steps` contains the steps the current emitter reports. `coverage: declared-steps-only` states that it is not a complete execution trace. Module revision, parser version, and transformation revision are explicit `null` until captured.
- `publisher_terms` separates observed publisher metadata, Quill source configuration, and not observed. Publisher labels/URLs are retained only when the record declares publisher metadata and the evidence fields were extracted. Configuration is not publisher evidence. Missing evidence is not a conclusion that terms are absent, restrictive, or permissive.

## Capture boundary and limitations

Capture currently covers only requests made through `packages/pipeline-core/src/utils/http.ts` inside `runModule`. Direct use of global `fetch`, custom HTTP clients, pre-built/cached/committed datasets, and most MCP-only tool fetch paths are not automatically captured. Only module-run requests whose redacted URL matches a record's source URL are attached by the current claim hook. Explicit record-level `source_artifacts_evidence` is retained separately from shared-client captures; it does not suppress a matching request capture. URL matching is not record lineage. A fully evidence-grade row-level chain still requires fetcher-specific linkage from each record to exact source artifact(s), transformation code/version provenance, and retained or reproducibly addressable raw artifacts.

The capture timestamp is recorded after the response body has been read. Original request query values, fragments, and URL credentials are removed before persistence; `url_redacted` signals information loss and the retained URL may not identify a versioned artifact completely. Retries can yield multiple captured response artifacts. Claim registration does not mint a source retrieval time: `retrieved_at` is null/absent unless a retained, URL-associated artifact supplies that timestamp. The separate claim-store `created_at` is Quill's registration time. The current `runModule` flow registers claims as a best-effort side effect and does not fail ingestion if evidence capture or claim persistence fails.

Use `null`, empty evidence arrays, and `not-captured`/`not-recorded` states as unknown/not available, never as rights or provenance determinations. Existing citation JSON rows without v1 evidence remain readable; the read adapter preserves their record hash but drops legacy registration-time values from source `retrieved_at`. Source terms must be checked with the publisher for the particular dataset and use.
