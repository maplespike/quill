### 1.9 Docs build integration (CRITICAL — Momus blocking issue)

The docs are generated by `scripts/build-docs.mjs` at repo root, which outputs to `packages/portal/docs/`. After Astro migration, only `public/` gets copied to `dist/`. **Docs must be in `public/docs/` before Astro build**.

**Fix**: The `Dockerfile.portal` (root) and CI/CD workflow must run `node scripts/build-docs.mjs` BEFORE the Astro build, and output docs into `packages/portal/public/docs/`.

Two possible approaches:
- **(A) Build-time**: Run `scripts/build-docs.mjs` with output dir as `packages/portal/public/docs/` before Astro build
- **(B) Dockerfile**: Keep docs generation outside Astro, copy `docs/` directly into the nginx image alongside Astro `dist/`

**Recommendation**: Approach (B) — simpler, no risk of Astro doing unexpected things with docs content. In the Dockerfile:
```dockerfile
# Build stage — Astro
COPY packages/portal/ ./portal/
RUN cd portal && pnpm build    # outputs portal/dist/

# Final stage — nginx serving Astro dist + docs
COPY --from=builder /app/portal/dist/ /usr/share/nginx/html/
COPY packages/portal/docs/ /usr/share/nginx/html/docs/
```

**Verification**: After build, `dist/docs/` exists and contains VitePress-generated content.

### 4.1 Update Dockerfile.portal at repo root (CRITICAL — CI/CD builds this, NOT packages/portal/Dockerfile)

The CI/CD workflow (`deploy-dev.yml` line 117: `file: Dockerfile.portal`) builds from `Dockerfile.portal` at repo root. The local `packages/portal/Dockerfile` is NOT used by CI — keep it for local testing.

```dockerfile
# Dockerfile.portal — Astro build + nginx serve
# CI/CD builds this at repo root (file: Dockerfile.portal)
FROM node:22-alpine AS astro-builder
WORKDIR /app
COPY pnpm-lock.yaml package.json ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY packages/portal/ ./portal/
RUN cd portal && pnpm build
# Generate docs into a separate location
COPY scripts/ ./scripts/
RUN node scripts/build-docs.mjs && cp -r packages/portal/docs/ ./portal/dist/docs/

FROM docker.io/nginx:alpine
COPY --from=astro-builder /app/portal/dist/ /usr/share/nginx/html/
COPY packages/portal/nginx.conf /etc/nginx/conf.d/default.conf

# Non-root user support (K8s securityContext runAsUser: 1001)
RUN mkdir -p /var/cache/nginx/client_temp \
    && mkdir -p /var/cache/nginx/proxy_temp \
    && mkdir -p /var/cache/nginx/fastcgi_temp \
    && mkdir -p /var/cache/nginx/uwsgi_temp \
    && mkdir -p /var/cache/nginx/scgi_temp \
    && chmod -R 777 /var/cache/nginx
RUN sed -i 's|pid\s*/run/nginx.pid;|pid /tmp/nginx.pid;|' /etc/nginx/nginx.conf

EXPOSE 8080
CMD ["nginx", "-g", "daemon off;"]
```

**Important**: The `scripts/build-docs.mjs` generates static docs. After Astro build, the docs must be copied into `portal/dist/docs/` so nginx serves them at `/docs/`.

### Lessons Learned

1. **Avoid Radix compound components in Astro SSR** — `Tabs`, `Sheet`, `Dialog` etc. use React context that Astro's server renderer doesn't preserve. Use plain HTML + `<script>` for interactive UI.
2. **Subagent scope creep is real** — Every subagent created files outside the portal (test files, CI workflows). Pin them with `MUST NOT DO: touch any file outside packages/portal/`.
3. **Docker build is the only honest test** — Local `pnpm build` works but Docker exposes missing deps, configs, tsconfig extends. Run it early.
4. **Monorepo `pnpm install --frozen-lockfile` in Docker** — needs `.npmrc`, `pnpm-workspace.yaml`, all `package.json` files for workspace members. Test in CI-like environment.
5. **`i18n/fr-CA`: SSR pages missing** — Astro config has no i18n routing. French only works via client-side `?lang=fr-CA`. Would need Astro i18n integration for `/fr/` routes.
