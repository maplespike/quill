## What actually went wrong today (root-cause chain)

1. **530 outage root cause:** zero Quill workloads existed in the cluster after the
   nixos drop; all manifests pinned the dead `nexus:5000` registry.
2. **forge node is flapping** — it rebooted, rejoined, then went offline again within
   the hour (Tailscale: `offline, last seen 3h ago`). Its kubelet is gone, so its pods
   became undeleteable zombies and it hosts the k3s **containerd image store** that
   had our imported images.
3. **etcd quorum broke** when forge dropped while sentry-agent was Unknown →
   `ServiceUnavailable` for the whole API server. Nexus + sentry restored 2/3 quorum.
4. **PVC deadlock:** the pvc-protection finalizer wouldn't clear while the API pod
   referenced the volume, and the pod couldn't start because the PVC was never bound.
   Broken by force-deleting the pod.
5. **WFTFC scheduler-binder stall:** the recreated PVC had pods scheduled to nexus but
   never got the `volume.kubernetes.io/selected-node` annotation, so the provisioner
   sat idle. Fixed by annotating the PVC manually:
   `kubectl -n maplespike annotate pvc quill-api-data volume.kubernetes.io/selected-node=nexus`

## The fix path that worked

1. **Build images on nexus itself** (docker 29.8 is installed there; the build context
   was rsynced to `~/quill-build`). FROM lines were qualified to
   `docker.io/library/...` so podman/docker short names resolve anywhere.
2. **Import into nexus k3s containerd**: `docker save` → `k3s ctr images import`.
   Images now exist as `docker.io/library/quill-{api,mcp,portal}:local` — no registry
   dependency at all.
3. **Retarget `values-prod.yaml`**: `image.registry: docker.io/library`, `tag: local`,
   `pullPolicy: Never` (forbids network pulls), api storage `nodeName: nexus`,
   cloudflared nodeSelector `nexus`. The whole stack is pinned to the only node with
   demonstrated uptime.
4. **Helm upgrade** after force-clearing forge zombie pods.

## Known follow-ups

- **forge** needs hands-on attention (power/HW check). Until then it's a liability:
  with 2/3 etcd voters, one more node loss = cluster outage. Consider `kubectl delete node forge`
  + `k3s etcd` member removal to at least stop zombie-pod churn, or restore forge to
  re-achieve 3/3.
- The scheduler-binder stall (item 5) is worth an issue: recreate-pod didn't fix it,
  only the manual annotation did (k3s v1.37 behavior).
- Registry strategy: when a real registry is wanted again, GHCR needs a token with
  `write:packages` (the earlier push failed on scopes). Until then, per-node
  `ctr import` is the doctrine; note images are per-node — new nodes need imports.
- `quill-ingest` image was never built/imported on nexus — required before re-enabling
  any ingestion cronjob.
