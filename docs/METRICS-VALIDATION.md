# Metrics Validation

MapleSpike has automated checks to ensure documented metrics match the codebase.

## Source of Truth

`docs/metrics.json` is auto-generated by `scripts/generate-metrics.mjs`. It reads directly from:

- **Modules**: `packages/pipeline-core/src/registry/registry.ts` (registry entries)
- **MCP Tools**: `packages/quill-mcp/src/tools/index.ts` (tool definitions)
- **TypeScript**: `find packages -name '*.ts' -not -path '*/node_modules/*' -not -path '*/dist/*'` (file count + line count)

## CI Validation

The CI workflow (`ci.yml`) runs two checks:

1. **Validate metrics.json is up to date** — Runs the generator and fails if metrics.json differs from generated output:
   ```bash
   node scripts/generate-metrics.mjs
   git diff --exit-code docs/metrics.json
   ```

2. **Metrics drift check** — `.github/workflows/metrics-drift-check.yml` runs the same generator and fails on `git diff --exit-code docs/metrics.json`. Date stamps stay as committed when the counts do not change, so the diff does not fail just because the calendar day changed.

## Auto-Fix

`scripts/fix-metrics.sh` updates README.md and AGENTS.md files with current metric values from metrics.json:

```bash
# Generate metrics
node scripts/generate-metrics.mjs

# Dry-run to see what would change
./scripts/fix-metrics.sh --dry-run

# Apply changes
./scripts/fix-metrics.sh
```

## Workflow

When adding modules or tools:

1. Make code changes (add registry entry, tool, or files)
2. Run metrics update:
   ```bash
   node scripts/generate-metrics.mjs && ./scripts/fix-metrics.sh
   ```
3. Commit the updated `docs/metrics.json`, `README.md`, and `AGENTS.md` files
4. CI validates everything matches

## Manual Override

If a metric is intentionally different (e.g., placeholder count vs live count), add a comment in metrics.json's description field explaining the discrepancy.
